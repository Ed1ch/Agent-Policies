# Codex CLI — правила

**Область:** общие правила Codex CLI для разных проектов. Конкретный хост, ветка, worktree, модель, полномочия и ADR определяются применимыми проектными инструкциями. Наличие task runner и его гарантии определяются конкретным проектом. Например, принятый runner Zanevka MCP v2 описан в [проектной инструкции](https://github.com/Ed1ch/zanevka-mcp-v2/blob/main/docs/operations/codex-runner.md); общие правила не заменяют его команды и ограничения.

1. Перед запуском уточни задачу, рабочий каталог, хост, права, ветку/HEAD и `git status`.
2. Проверь, не выполняется ли та же задача другим Codex. После timeout не запускай второй экземпляр без проверки первого. См. [PROCESS_MANAGEMENT.md](PROCESS_MANAGEMENT.md).
3. Не теряй чужие изменения; `reset --hard`, `clean -fd`, force push, merge, удаление веток — только по разрешению.
4. Устанавливать ПО, менять ОС/сеть, перезапускать службы — только с разрешения в рамках [GENERAL.md](GENERAL.md).
5. По завершении укажи статус, ветку, diff/PR, тесты и оставшиеся риски. Код завершения не заменяет проверку результата.

## Продолжение задачи и смена модели

Продолжение **уже начатой задачи** выполняется на той же модели и с тем же reasoning effort (тем же пресетом), что и предыдущая попытка, в том числе после остановки, таймаута или исчерпания лимита.

Сменить модель или пресет для этой задачи можно **только по согласованию с пользователем**. Такая смена означает начало задачи заново с исходной базы: незавершённые изменения предыдущей модели автоматически не передаются новой. Отдельное задание на анализ или ревью считается самостоятельной задачей, а не продолжением реализации.

Правило относится к постановке и ведению задач; специальных проверок и блокировок в runner не требуется.

Приёмка и merge остаются за пользователем, если прямо не делегированы. Инструкции не гарантируют защиту от параллельного ручного запуска. Ранее существовавшее задание не является разрешением на новый запуск без проверки его актуального состояния.
