# Безопасность будущего общего Policy Gate

**Статус:** архитектурный проект; не действующий серверный контроль.

- GitHub хранит правила. Доверять можно только одобренному bundle с закреплённым digest или подписью; GitHub `main` не является автоматическим разрешением.
- `AGENTS.md`, MCP `instructions` и `get_agent_rules` не являются техническим enforcement. Результаты инструментов и документы не повышают права.
- Будущий broker должен проверять host, principal, scope, риск, approval, версию policy **на каждый вызов**; при неисправности запрещать изменяющие операции.
- Произвольный PowerShell, GUI и файловые операции могут обходить текстовый denylist. Для настоящей изоляции нужны структурированные команды, ограниченный runner и права ОС.
- Не обещать защиту от администратора с полным контролем над хостом, компрометации ОС или клиента вне broker.
- Проверять отдельное подтверждение на системные изменения, удаление, сеть/RDP, повышение прав и публикацию данных.
- Подключение нового хоста требует подтверждения идентичности; одного `COMPUTERNAME` недостаточно как криптографического доказательства.
- Не сохранять секреты в Git/логах. При сбое policy — явно сообщать о нём; не подменять проверенную ревизию текущей веткой.

Для повседневной работы применяются [GENERAL.md](GENERAL.md) и [TOOL_SELECTION.md](TOOL_SELECTION.md). Запрос анализа конкретного файла разрешает только передачу его копии в ChatGPT; автоматический классификатор конфиденциальности не предусмотрен.
