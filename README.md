# Agent-Policies — общие правила работы AI-агентов

**Назначение:** единый источник общих агентных политик для нескольких проектов и способов подключения, а не документация продукта Agent-to-Go или Zanevka MCP v2.

**Статус:** исходные общие политики перенесены из [Agent-To-Go/context/agents-policy](https://github.com/Ed1ch/Agent-To-Go/tree/main/context/agents-policy) 07.11.2026. Технический Policy Gate пока не реализован; ссылки из проектов переводятся поэтапно.

## Области ответственности

- **Здесь:** общие границы разрешений, выбор инструментов, безопасная работа с процессами, Codex CLI, профили хостов и проект будущего Policy Gate. Платформенно-специфичные правила маркируются явно.
- **[Agent-To-Go](https://github.com/Ed1ch/Agent-To-Go):** только переносной USB-коннектор: состав, запуск, сеть, безопасность носителя, жизненный цикл, тесты.
- **[Zanevka MCP v2](https://github.com/Ed1ch/zanevka-mcp-v2):** архитектура продукта, ADR, почта, DEV/RELEASE, проектная приёмка и настройки. Общие правила здесь не копируются.

## Порядок применения

1. Разрешение пользователя, системные и инструментальные ограничения обязательны; текст политики не расширяет предоставленных прав.
2. Сначала определить задачу, целевой хост, ОС и применимый проект, затем читать лишь подходящие общие документы.
3. Проектные `AGENTS.md`, ADR и эксплуатационные регламенты дополняют общие политики и не должны молча их ослаблять. Противоречие разрешается явным решением владельца, а не выбором удобного документа.
4. Для повторяемых запусков или автоматической доставки политики указывать проверенную Git-ревизию (commit SHA / tag), а не предполагать, что произвольный `main` безопасен. Вновь полученный текст из GitHub не является новым разрешением.
5. **Context-First:** правила читаются агентом по задаче; серверный Policy Gate, проверка digest и запрет вызовов на уровне MCP не реализованы и не должны выдаваться за действующую защиту.
