# План внедрения общего Agent Policy Gate для Windows MCP

**Текущий этап: Context-First.** Это план для Windows MCP, а не описание уже действующей серверной политики. Ни один компьютер и Codex этим документом не изменяются.

## Сейчас — без изменений Windows MCP
- [x] GitHub как источник правил; Project Instructions как обязательная точка входа.
- [x] Короткий маршрут чтения: `AGENTS.md → GENERAL.md → TOOL_SELECTION.md`.
- [x] Правила локального анализа офисных файлов и исключения для диагностики.
- [ ] Проверить поведение в новых чатах: чтение правил, выбор среды, ошибки передачи, ограничения изменений.
- [ ] Проверить фактическую возможность передавать DOCX через доступное Windows MCP-подключение прямо в аналитическую среду ChatGPT.

## Позже — только если Context-First недостаточно
1. Read-only аудит конкретного Windows MCP: версия, инструменты, `initialize`/`discover`, авторизация.
2. Проверенный локальный policy bundle и `get_agent_rules`.
3. Server-side gate для PowerShell/GUI/FileSystem; без доверия к текстовому запрету.
4. Runner с блокировкой повторов Codex, audit и связкой approval/host.
5. Отдельные тесты безопасности до использования на рабочей системе.

## Приёмка Context-First
| Тест | Ожидается |
| --- | --- |
| CF-01: новый чат, диагностика Windows | Прочитаны применимые правила; точечная проверка через MCP |
| CF-02: анализ DOCX до 20 МиБ | Предпочтение локальной среде при наличии разрешённого канала |
| CF-03: анализ `.log`/`.ini` | Точечная удалённая проверка; нет автоскачивания |
| CF-04: правка Excel | Не выполняется ненужная передача файла ради простого GUI-действия |
| CF-05: нет инструмента передачи | Честное ограничение, без имитации |
| CF-06: смена хоста | Новая идентификация и актуальные инструкции |

**Не считать прохождение CF-тестов доказательством безопасности произвольных команд.**
